What the daily count means

A user counts when at least one add-in was loaded on that client-local date. The count remains after the add-in closes. An add-in left open can record subsequent days. Offline reports fill their original dates; older monthly-only markers cannot supply missing daily detail. No AI commands or content are needed for licensing.

LogPath is not a license counter

Counts represent recorded feature invocations, not completed AI operations. Prompts, document text, token consumption and costs are never imported. User hashes cannot be joined to license identities. Agent-labelled events are shown separately, but a launch or UI click does not prove autonomous work completed.

Usage Server configuration

Import sources, publishing, billing and retention settings apply on Save. Listener, TLS and security settings require restart.

Not loaded

Settings are validated and written atomically. LogPath/LicenseCounter sources are scanned automatically after Save. Missing or inaccessible folders are reported; no log forwarding is performed by the server itself.

Data retention and cleaning

Define how long licensing and function history should be kept; reject older offline replays at collection time

Set retention.cutoff_date or retention.keep_months above, save, and restart the server. The later of these dates is the effective boundary. A rolling limit keeps the database from growing indefinitely. Licence evidence is removed only when it cannot prove a qualifying load on or after that date. Imported source files and local client markers are not deleted.

Preview before running a destructive cleanup.

The cutoff also applies to subsequent HTTP and file imports. Old markers receive an acknowledgment but are discarded, preventing endless retries; expired log events are ignored. Export historical reports and create a verified database backup before deletion.

Administrator sign-in

Optional password-free sign-in on this machine only

The policy is encrypted and checked against a key in the separately protected secrets.json file. Password-based sign-in remains available. Protect the entire data directory using Windows NTFS permissions. Not intended for untrusted users sharing the same computer.

Access tokens and add-in setup

Rotate tokens independently; a rotation invalidates the previous token immediately

For installations migrated from v1.2, old token plaintext is not recoverable. Rotate once to obtain a new token. Copy and update all affected add-ins immediately after rotation.

Complete client URLs

Copy these exact links into the add-ins or deployment configuration. The links contain bearer tokens: treat them as passwords and do not publish them in logs or screenshots.

Links use the address in your browser. For clients on other computers, open the server using its reachable HTTPS hostname before copying. Links are unavailable until the relevant token is known or rotated.
