RED INK SEMANTIC ARCHIVE WORKER
===============================

Purpose
-------
redink-sa-worker.exe performs Semantic Archive discovery, extraction/OCR,
semantic metadata/index generation, publication and permission maintenance
without opening Word or Outlook user interface dialogs.

The worker uses the same Red Ink configuration resolution as the Office add-ins.
Normally you do NOT need to provide a redink.ini path.

Quick start
-----------
Index or update one archive and continue until the operation is drained:

  redink-sa-worker.exe refresh "DP Know-how"

The archive can be addressed by its unique display name or stable archive ID.
The quick syntax automatically uses all documents and loop mode.

Common operations
-----------------
  refresh      Discover new/changed/removed sources, reuse valid existing work,
               extract/index what is needed, and publish the current generation.
               Use this for first-time indexing and normal updates.

  retry        Retry failed/deferred source work that is ready to run.

  reindex      Rebuild semantic metadata/indexes while reusing valid extracted text
               whenever possible.

  extract      Force re-extraction (and OCR where configured) before rebuilding
               semantic metadata. This can be expensive; do not use it for a normal
               refresh unless extraction itself must be redone.

  permissions  Reconcile derivative permissions only; no content indexing.

Examples
--------
First build / normal update:
  redink-sa-worker.exe refresh "DP Know-how"

Retry ready failures:
  redink-sa-worker.exe retry "DP Know-how"

Rebuild semantic metadata:
  redink-sa-worker.exe reindex "DP Know-how"

Force extraction/OCR again:
  redink-sa-worker.exe extract "DP Know-how"

Throttle processing pressure:
  redink-sa-worker.exe refresh "DP Know-how" --batch-files 8

Allow larger processing batches:
  redink-sa-worker.exe refresh "DP Know-how" --batch-files 128

Limit each source-discovery pass to 20 seconds:
  redink-sa-worker.exe refresh "DP Know-how" --discovery-seconds 20

Use an explicit Red Ink configuration source (optional override):
  redink-sa-worker.exe refresh "DP Know-how" --ini "D:\Config\redink.ini"

Process every archive in the local catalog:
  redink-sa-worker.exe --all-archives --all-documents --operation refresh --loop

Defaults
--------
Foreground worker defaults are intentionally more aggressive than Office idle
background processing:

  Processing files per batch:       64
  Discovery entries per pass:       5000
  Discovery time per pass:          60 seconds
  Delay between continuation cycles: 1 second

Use --batch-files to reduce OCR/model load if needed. A smaller batch size does
not discard completed work; it only spreads the operation across more cycles.

Central library synchronization
-------------------------------
If SemanticArchiveCatalogLibraryPath is configured, the worker synchronizes the
central Semantic Archive library into the local subscription catalog before it
resolves the requested archive. This means a user can process a centrally
published archive without first opening Outlook solely to synchronize the library.

If the library is temporarily unavailable, personal/publisher archives can still
be processed. Subscribed archives remain subject to their normal library and ACL
validation when used.

Progress and logs
-----------------
In an interactive console, the current activity is shown on stderr as one
in-place status line that rewrites itself, for example:

  Processing source — policy.pdf | 18 completed; 112 queued

stdout remains JSON-lines so scripts can parse lifecycle/batch events. If --log
is supplied, the same JSON events are also written to that private log file.

A message such as "Source discovery has a durable continuation" means the scan
stopped at its bounded discovery checkpoint and will continue in the next cycle.
The current number of source jobs is therefore NOT necessarily the final number
of physical files in the directory.

Safe cancellation
-----------------
Press Ctrl+C to request graceful cancellation. The worker propagates a
CancellationToken and stops at a safe checkpoint. Durable discovery/extraction
checkpoints remain reusable, and generation activation is atomic. Run the same
command again to continue.

Avoid forcibly terminating the process (for example Task Manager / End Process)
when a normal Ctrl+C can be used. A forced process kill cannot give in-flight
external OCR/model calls a chance to stop cleanly, although the last validated
published generation remains protected by atomic publication.

Office-host limitations
-----------------------
The worker does not automate Word or Outlook UI. A source format that requires an
Office host reader can remain pending/host-required and should later be processed
from the appropriate Office host.

Model output tolerance
----------------------
Semantic metadata output is normalized before strict validation. In particular,
Title or Summary returned as a JSON array of strings is normalized to the scalar
string contract instead of causing the whole source to fail. Final stored metadata
still follows the strict Red Ink schema.

Advanced syntax
---------------
  redink-sa-worker.exe [--ini <path-or-HTTPS-URL>] [--once|--loop]
    (--archive <name-or-stable-id> [--archive <name-or-id> ...]|--all-archives)
    [--document <stable-id> [--document <id> ...]|--all-documents]
    [--operation refresh|retry|reindex|extract|permissions]
    [--operation-id <GUID>]
    [--batch-files 1..4096]
    [--discovery-entries 1..10000]
    [--discovery-seconds 1..120]
    [--interval-seconds 1..86400]
    [--max-cycles 1..1000000]
    [--max-seconds 1..604800]
    [--log <private-file-outside-source-roots>]

Exit codes
----------
  0    Operation completed
  1    Configuration, authentication or runtime error
  2    Invalid command-line arguments
  3    Work remains incomplete/deferred/failed after the requested run mode
  130  Graceful cancellation requested

Configuration requirement
-------------------------
SemanticArchiveCatalogPathLocal must be configured. If it is not configured,
Semantic Archive is disabled and the worker cannot process archives.

For all available switches, run:
  redink-sa-worker.exe --help
